Annotation Rules:

1. VULNERABILITY SPANS
Identify the exact text substring that represents the vulnerability or risk. Apply the closest matching taxonomy label.
When in doubt between two labels, apply both — over-tagging is preferred over under-tagging.

2. ENTITY SPANS
Tag every person mentioned in the note, even if they have no vulnerability of their own (e.g. a family member mentioned in passing). There are three entity types:

- `Person_Name`: a proper name or pseudonym e.g. "James", "Mrs Ahmed", "[Person1]"
- `Person_Role`: a descriptive role or relational label e.g. "tenant", "his mother", "the children", "support worker"
- `Person_Pronoun`: a pronoun used as the PRIMARY reference to a person, only where no nearby name or role has been established. For example, tag "she" in "she has asthma" only if no name or role for that person appears nearby. Do NOT tag every pronoun — only tag it when the pronoun is doing the sole attributional work.

When a person has both a name and a role mentioned nearby, prefer linking to the name span.

3. ENTITY LINKING
Link each vulnerability span to the entity it belongs to. Leave a vulnerability unlinked if:
- The responsible person cannot be identified from context, OR
- The label is a property-level label (property_level_*) — these are NEVER linked to a person.

4. DISAMBIGUATION
If multiple people are mentioned, ensure each vulnerability is linked to the correct person. A vulnerability belonging to a household member should be linked to that member's entity span, not to "tenant".

5. DUAL LABELLING
Apply both labels when a span clearly implies two vulnerabilities:
- A physical assault in a domestic abuse context: apply both `safety_risk_domestic_abuse` AND `cautions_physical_abuse_or_threat_of`
- A hospital stay that also implies displacement: apply both `health_care_setting` AND any other relevant label
- A utilities failure where the tenant depends on medical equipment: apply both `housing_conditions_utilities` AND `health_medical_life_sustaining`

---

Commonly Confused Labels — read carefully:

| Situation | Correct label |
|---|---|
| Adaptation needed but not yet installed (e.g. "needs a wet room") | `disability_requires_adapted_property` |
| Adaptation already installed (e.g. "property has a wet room") | `property_level_property_adapted` |
| Background care history (was fostered, grew up in social care) | `care_care_setting` |
| Current placement in hospital, care home, hospice, or staying with family due to health | `health_care_setting` |
| Bereavement or pregnancy | `life_events_temporary` — NOT `health_care_setting` |
| Physical violence in a domestic relationship | Both `safety_risk_domestic_abuse` AND `cautions_physical_abuse_or_threat_of` |
| "Struggling" or "not coping" alone | Do NOT apply `health_mental_health` unless mental health is clearly implied by context |
| Tenant staying with family as incidental context | Do NOT apply `health_care_setting` — only apply if displaced due to health/vulnerability |
| Tenant has financial issues | Do NOT apply `safety_risk_gas_capped` — only apply if 'gas cap' specifically mentioned |

Output Format:
Return the data as a JSON object with two keys:
- `labels`: a list of {"text": <exact substring>, "label": <taxonomy label>}
- `links`: a list of {"from": <vulnerability text>, "to": <entity text>}

Text values in links must be copied exactly from the corresponding label entries.
Return only the JSON object — no preamble, no explanation, no markdown formatting.
